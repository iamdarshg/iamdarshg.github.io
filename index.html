Builder first, theory close behind.

I like projects where physics and code have to negotiate with real hardware: PCBs that need to be manufacturable, firmware that has to survive noisy sensors, and simulations that should help decisions rather than just make pretty plots.

The through-line is simple: learn the underlying math, build a working artifact, document the failure modes, then iterate. That loop currently runs across aerospace, RF, embedded control, and ML-assisted design.
